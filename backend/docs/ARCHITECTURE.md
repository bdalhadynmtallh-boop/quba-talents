# بنية المشروع ودليل التطوير

## الحدود والمسؤوليات

المشروع يحتفظ بالمجلدين الرئيسيين `frontend` و`backend`، والتقنيات الحالية. صفحات الموقع هي الرئيسية، قسم الطلاب الموهوبين، والتسجيل. الدخول صفحة مساعدة للإدارة. ملفات الطلاب والأعمال والسير والمرفقات خاصة بالمسؤول؛ التسجيل لا ينشئ حساب طالب.

```text
frontend/src/
  app/                        التوجيه والثيم
  pages/                      تركيب الصفحات وربط المسارات
  features/
    students/                 إدارة الطلاب وملف الطالب
    registrations/            التسجيل ومراجعة الطلبات
    works/                    نماذج الأعمال وعرض المرفقات
    cv/                       المعاينة والتحرير والتصدير
    school/                   إعدادات المدرسة والسنة والكتالوج
    auth/                     حالة الجلسة وحراسة العرض
  components/                 عناصر واجهة مشتركة والتخطيط
  lib/                        HTTP وحماية الطلبات وتحميل الموارد
  styles/                     العربية وRTL والثيمان والجوال

backend/src/
  modules/<domain>/routes.ts   HTTP والتحقق والمصادقة وحالة الاستجابة
  modules/<domain>/service.ts  منطق الميزة ومعاملاتها
  modules/*/repository.ts     عمليات قاعدة متكررة وحدود الأقفال
  modules/*/serialization.ts  تحويل السجلات إلى استجابات واضحة
  services/                   اتصال AI وPDF والتخزين
  plugins/                    تركيب المصادقة والحماية والقاعدة
  config/                     التحقق من إعدادات الخادم
  lib/                        الأخطاء ومعرّفات المسارات

backend/shared/src/
  index.ts                    الصادرات العامة المستقرة للحزمة
  normalization.ts            تطبيع النص العربي ومفاتيح الأسماء
  constants.ts                الثوابت المشتركة
  schemas/<domain>.ts         مخططات الإدخال وأنواع كل مجال
```

ملفات `node_modules` و`dist` و`src/generated` مولدة؛ لا تُعدل يدويًا. تقسيم الحزمة المشتركة لم يغيّر أسماء صادراتها أو صيغة البيانات الحالية، بما فيها رقم الجوال والسير القديمة المتوافقة.

## إضافة وظيفة جديدة

1. حدّد المدخلات وحدودها في مخطط المجال المناسب في `backend/shared/src/schemas`.
2. أضف العملية في خدمة المجال. مرّر الاعتماديات صراحةً؛ الخدمة لا تعتمد على `FastifyRequest` أو `FastifyReply`.
3. أضف المسار في `routes.ts`: حماية المسؤول، تحليل المدخلات، استدعاء الخدمة، ثم الاستجابة.
4. أضف الواجهة داخل الميزة المناسبة، واترك ملف الصفحة لتركيبها. استخدم عناصر التحميل والأخطاء والنوافذ المشتركة.
5. اختبر السلوك وحدود الوصول والفشل. تغيير العلاقات أو البيانات يحتاج خطة ترحيل وموافقة منفصلة.

خدمات المجال تحتفظ باستعلامات Prisma القريبة من قواعد عملها. نستخدم مستودعًا عندما توجد عملية أو علاقة متكررة، مثل قفل الطالب أو قراءة المدرسة؛ لا نضيف طبقات تغلف كل استعلام دون حاجة.

## قواعد المعاملات والأقفال

- العميل الذي تبدأ به المعاملة يُمرر إلى القراءات والكتابات التابعة لها. `cvSource(tx, id)` لا يعود إلى اتصال التطبيق الرئيسي.
- ترتيب الأقفال عند الحاجة: السنة الدراسية، ثم الطلاب بترتيب المعرّفات، ثم إعدادات المدرسة، ثم الفصل والمواهب بترتيب المعرّفات، ثم العمل.
- كل تعديل على حقيقة تخص الطالب أو أعماله يقفل الطالب عبر `students/repository.ts` قبل الكتابة. الحذف والرفع والتحرير يستخدمون الحد نفسه.
- حفظ السيرة واعتمادها يستخدمان قفل الطالب وأقفال مشاركة لبيانات المدرسة والكتالوج. التغييرات المتزامنة في هذه المصادر لا تتجاوز فحص بصمة المصدر.
- قراءة مصدر السيرة وحالتها تستخدم `RepeatableRead` للحصول على لقطة متسقة. الحفظ والاعتماد يستخدمان `revision` لكشف تعارض النسخ.
- طلب AI ومعالجة الملفات وتصدير PDF خارج المعاملات؛ المعاملة تحفظ النتيجة أو البيانات المرتبطة فقط.
- مفتاح إعادة إرسال التسجيل له قفل استشاري داخل المعاملة بعد قفل السنة. الاسم والجوال ليسا هوية فريدة.
- يحفظ اعتماد السيرة `CvReview` مع نسخة المسودة قبل زيادة `revision` في المعاملة نفسها. تاريخ مراجعة الطالب هو وقت إقرار المسؤول بها، وليس حسابًا أو توقيعًا إلكترونيًا للطالب.
- تعديل البصمة أو ترتيب حقولها قد يجعل السير المحفوظة قديمة. لا تغيره بوصفه تنسيقًا تجميليًا.

## التحقق المعزول

الاختبارات التي تكتب تتطلب `TEST_DATABASE_URL` لقاعدة مستقلة ينتهي اسمها بـ`_test`. اختبارات المتصفح تتطلب أيضًا `BROWSER_TESTS_ALLOW_DB_WRITE=yes`. لا تستنتج اتصال الاختبار من ملفات `.env`، ولا تستخدم اتصال قاعدة التطوير أو الإنتاج.

اختبار الإدارة يشغّل API وVite خاصين به على المنفذين `3003` و`5189`. اختبار السيرة يستخدم `3002` و`5187`، والرئيسية `5188`. التخزين المؤقت لكل رحلة داخل مجلد منفصل. الاختبارات تنظف سجلاتها؛ بعضها يغير السنة وإعدادات المدرسة داخل قاعدة الاختبار، لذلك يجب تخصيص القاعدة بالكامل للاختبارات.

من جذر المشروع، مع اتصال الاختبار المعد مسبقًا:

```powershell
npm.cmd run build
npm.cmd run typecheck
npm.cmd run lint
$env:TEST_DATABASE_URL = 'اتصال_قاعدة_اختبار_مخصصة'
npm.cmd test
$env:BROWSER_TESTS_ALLOW_DB_WRITE = 'yes'
npm.cmd run test:browser
```

لا تنفذ `db:deploy` قبل التحقق من قاعدة الوجهة. تجهيز قاعدة اختبار فارغة يحتاج تطبيق ترحيلات المشروع عليها وحدها. مفاتيح AI الحقيقية ليست مطلوبة لاختبارات العقود أو رحلة السيرة الوهمية.

في بيئات Windows التي يتعذر فيها تشغيل `tsx` يمكن ترجمة اختبارات الخادم بالمترجم الموجود وتشغيلها بـNode، دون تثبيت مكتبة بديلة:

```powershell
node node_modules/typescript/bin/tsc -p backend/tsconfig.tests.json --noEmit false --rootDir backend --outDir .data/refactor-tests
```

لتجربة PDF من هذا المخرج، انسخ `backend/assets/branding` إلى `.data/refactor-tests/assets/branding`؛ القالب يحمّل الشعار محليًا نسبةً إلى موقع الخدمة. ثم شغّل الملفات المترجمة مع اتصال الاختبار:

```powershell
node --test --test-concurrency=1 '.data/refactor-tests/tests/*.test.js'
```

## حدود هذه المرحلة

هذه المرحلة تنظم المصدر وتصلح استخدام المعاملات وعزل الاختبارات. لا تضيف منع تكرار التسجيل أو مراجعة الطالب أو تغييرات علاقات جديدة، ولا تنشر إصدارًا. خطة قاعدة البيانات التالية في `DATABASE_PLAN.md` تحتاج موافقة قبل تنفيذها على البيانات الفعلية.
