# تقرير المشروع

تاريخ التحديث: 2026-10-10، Asia/Riyadh. الأجزاء الثلاثة منفذة داخل المشروع نفسه. وظائف الإدارة والحفظ والتصدير اختُبرت محليًا، وصياغة AI اختُبرت بعقد ونقل ومزود اختباري فقط. لا يتوفر مفتاح Qwen في البيئة الحالية، لذلك لم يُختبر الاتصال الحقيقي ولا توصف الصياغة الحقيقية بأنها ناجحة.

## الهيكل ومسؤولياته

```text
quba-talents/
  frontend/
    src/app/                 التوجيه والمصادقة والثيم
    src/pages/               الرئيسية والدخول والتسجيل والطلاب والملف
    src/features/            الطلاب والطلبات والأعمال والمدرسة والسيرة
    src/components/          التخطيط والنوافذ والتأكيد وحالات التحميل
    src/lib/                 HTTP وCSRF والموارد وتنزيل PDF
    src/styles/              RTL والثيمان والجوال
    tests/                   رحلات المتصفح
  backend/
    src/config/              إعدادات الخادم المتحققة
    src/plugins/             الجلسات والقاعدة والحماية والتخزين
    src/modules/             auth/students/registrations/works/school/cv
    src/services/ai/          اتصال Qwen النصي المباشر
    src/services/pdf/        قالب A4 وChromium وخرائط Unicode
    src/services/storage/    التحقق والتخزين وقائمة الحذف
    prisma/                  المخطط وأربعة ترحيلات وseed اختياري
    tests/                   عقود AI واختبارات الحماية والتكامل
    shared/src/              أنواع ومخططات Zod مشتركة مع الواجهة
    assets/branding/         شعار الوزارة المحلي للخادم ومصدره
    scripts/                 تجهيز أسرار البيئة دون عرضها
    docs/                    الخطة والتقدم وصور وPDF اختبار
  compose.yaml              PostgreSQL 17 مع volume دائم
```

المخرجات المولدة node_modules وdist وgenerated ليست مصدرًا للتعديل. المرفقات في backend/.data/uploads محليًا، وملفات .env والأسرار والمرفقات مستثناة من Git. work خارج المشروع يحوي أدوات الاختبار وPostgreSQL المحمول؛ ليس اعتمادًا للإنتاج.

## المنجز حسب الجزء

1. الأساس: React/Vite/TypeScript strict وnpm workspaces، Fastify/PostgreSQL/Prisma، المصادقة الإدارية وCSRF والجلسات، الرئيسية والتخطيط العربي والخطوط المحلية والثيمان. تمت إضافة الوثائق الناقصة عند بدء الجزء الثاني. لم تُستبدل التقنيات أو يُعد إنشاء المشروع.
2. الإدارة: الطلاب CRUD والبحث والتصفية وترقيم صفحات الخادم؛ حفظ دون سيرة أو أعمال؛ إنجازات منظمة ومعلومات نصية ومشرفون خاصون اختياريون. التسجيل طلب فقط، مراجعته وتعديله وقبوله أو رفضه ومعاملة تمنع تكرار الطالب. الأعمال CRUD ودور الطالب وتاريخ ورابط ورفع ملفات فعلي خاص. إعدادات المدرسة والشعار والمشرفين وترتيبهم محفوظة في PostgreSQL. لا حسابات طلاب ولا تخزين بياناتهم في localStorage.
3. السيرة: مصدر بيانات فعلي وخدمة Qwen مستقلة، JSON متحقق ومسودة وتحرير واعتماد وحماية من تعارض النسخ والطلبات المتكررة وتنبيه تغير المصدر؛ لا استدعاء AI عند القراءة أو التنزيل. PDF عربي حقيقي على الخادم من المعتمد، منفرد أو دفعة مع فهرس، خطوط محلية ونص قابل للاستخراج والبحث. حالات غير منشأة/مسودة/معتمدة وتحذير مغادرة التعديل غير المحفوظ. شعار وزارة التعليم الرسمي محفوظ محليًا في المعاينة والتصدير بطلب المستخدم.

حُفظت أسماء المشرفين الثلاثة التي زود بها المستخدم في إعدادات قاعدة التطوير بالترتيب المطلوب عبر API المسؤول، مع إعادة قراءة تؤكد الحفظ. لا تُحفظ الأسماء الحقيقية كافتراضات داخل الكود. المشرفون في PDF الاختبارات تجريبيون؛ قواعد الاختبار منفصلة عن هذه الإعدادات.

## مسارات API

كل المسارات أدناه تبدأ بـ/api. باستثناء CSRF والجلسة والدخول وإرسال طلب التسجيل، يلزم مسؤول مسجل. كل تغييرات البيانات تتطلب CSRF وOrigin مطابقًا. /health و/health/ready يكشفان صحة الخدمة فقط.

## القرارات وحدود التنفيذ

- PostgreSQL الفعلية هي مصدر الحفظ، مع Prisma 7.10 المستقر وpg adapter. الترحيلات الأربعة مطبقة ومقارنة المخطط الفعلي لا تظهر فروقًا.
- قبول التسجيل يقفل الطلب في معاملة؛ التكرار يرجع الطالب نفسه، وحذف الطالب لا يسمح بإعادة إنشائه من الطلب المعتمد بضغطة أخرى.
- ملفات JPEG/PNG/WebP/PDF فقط، 6 لكل عمل و10 MiB للملف، تحقق بنيوي وإعادة ترميز الصور وحد 16 مليون بكسل، أسماء عشوائية وحذف دائم قابل لإعادة المحاولة. لا HTML/SVG/تنفيذيات ولا جلب روابط الأعمال.
- Qwen native fetch داخل services/ai؛ مفتاح وعنوان الخادم غير مهيأين. تمت مراجعة وثائق Alibaba الحالية للمعرف الافتراضي qwen3.8-max وenable_thinking:false ومخرجات JSON حسب المنطقة. إعدادات النموذج النصي مستقلة عن أي خدمة مستقبلية.
- المدخلات النصية الضرورية فقط؛ لا هوية أو مرفقات أو روابط تلقائيًا. Zod يتحقق من مفاتيح وبنية وحدود الناتج، مع رفض تواريخ منظمة غير موثقة. التعليمات تمنع الاختلاق؛ صحة كل عبارة تحتاج مراجعة المسؤول، ولا يمكن ضمانها بمجرد نجاح validation.
- cvSchema version=2، مسودة ومعتمد ولقطة هوية وبصمة مصدر وrevision منفصلة. قفل التوليد بمهلة في القاعدة، والمزود خارج المعاملة. لا إعادة محاولات تلقائية ولا حفظ نتيجة مبتورة أو غير صالحة، ولا استبدال المعتمد عند إعادة الصياغة.
- AI: طلبان جاريان لكل عملية، 5/10 دقائق لكل IP، مهلة افتراضية 60 ثانية. PDF: عملية واحدة، 20 طالبًا و20 MiB و60 ثانية. الحدود المشتركة بين عدة عمليات ليست منفذة؛ يلزم مخزن حدود وتنسيق عند نشر عدة نسخ.
- Chromium حقيقي؛ A4 أبيض وRTL والخطوط والشعاران محليًا، escaping لكل النصوص وحظر الشبكة. ملاحظات الاستكمال خارج القالب والمشرفون في مجموعة واحدة في النهاية. خرائط Unicode تُطبع بالحروف العربية العادية مع بقاء شكل النص المتصل.
- هوية المعتمد ثابتة حتى اعتماد جديد. الشعار المدرسي الحالي وشعار الوزارة المحلي يظهران عند التنزيل؛ تغيير إعدادات المصدر يظهر تنبيهًا. التصدير لا يعدّل السير ولا يستدعي AI.
- React Router استُخدم بنمط data router لتفعيل useBlocker دون تغيير إطار الواجهة. نوافذ Escape تحترم رفض إغلاق التعديل، وعناوين النوافذ فريدة حتى عند التداخل.

## ما بقي أو لم يُختبر

### إعادة ترتيب المصدر وإصلاح التشغيل

بطلب المستخدم أصبح المصدر في frontend وbackend فقط، مع ملفات جذر مشتركة للتشغيل والتثبيت. نُقلت shared والتوثيق والأصول الخاصة بالخادم وأداة الإعداد تحت backend. حدّثت مسارات TypeScript وVite وPrisma واختبارات المتصفح وقراءة شعار PDF والتخزين؛ لم تُبدل التقنيات أو البيانات.

عند فحص بلاغ التشغيل كان package.json في الجذر يحمل تعريف @quba/shared، وREADME الرئيسي يحمل دليل الشعار، وكانت حزمة ZIP السابقة فارغة عند إعادة قراءتها. أُعيدت ملفات الجذر الصحيحة. أوقفت المعاينة التي كانت تحجز lightningcss، ثم نجحت npm ci بعد تحديث روابط workspaces. لم تُحذف قاعدة البيانات أو المرفقات أو حساب المسؤول، وdb:deploy أكد أربعة ترحيلات دون ترحيلات معلقة. إعداد المسؤول يبني shared تلقائيًا. وُحد منفذ المعاينة وAPP_ORIGIN على 5186 ليكفي npm run dev دون متغيرات يدوية. Docker أصبح يستجيب في بلاغ المستخدم لكن قاعدة إضافية تعارض المنفذ الحالي؛ لا يوجد تشغيل Docker ناجح متحقق، وتستمر النسخة الحالية على PostgreSQL الموجودة.

نتائج التحقق بعد إعادة الترتيب تُضاف عند انتهاء تشغيل الاختبارات، ولا تُستنتج من نتائج الهيكل السابق.

### إعدادات لم تتحقق بعد

1. إدخال AI_API_KEY وAI_BASE_URL الصحيحين وإجراء طلب حقيقي على Qwen ثم مراجعة الناتج. لا يمكن إتمام هذا الاختبار دون مفتاح صالح؛ لا يملك المشروع مزودًا وهميًا يمكن تفعيله في الإنتاج.
2. Docker Desktop تعطل قبل بدء المحرك؛ Compose موجود لكن تشغيله الفعلي لم يُتحقق. المعاينة تعمل على PostgreSQL 17 محمولة دائمة محليًا، والتشغيل موثق في README.
3. إنشاء المسؤول التفاعلي لم يُختبر تفاعليًا؛ compiled/typechecked، والدخول بحساب المعاينة اختُبر. لا نشر إنتاج أو وكيل HTTPS أو تثبيت Chromium على Linux أو Safari أو استرجاع نسخة احتياطية فعلي في هذه الجلسة. الإرشادات موجودة ولا تمثل نجاح اختبار.
4. npm audit أبلغ عن 4 تنبيهات عالية في اعتماديات Prisma غير المباشرة (@prisma/config/deepmerge-ts/mysql2/prisma). لم يُستبدل Prisma المستقر بإصدار تجريبي أو downgrade قسري. المحول المستخدم PostgreSQL، لكن يلزم معالجة اعتماديات الأدوات ومراجعتها قبل الإنتاج؛ لا ادعاء بإغلاقها أو أمان شامل.
5. التخزين الإنتاجي يحتاج STORAGE_DIR على قرص دائم أو محول تخزين كائنات، وأسرار مستقلة وخطة نسخ قاعدة ومرفقات واسترجاع مختبرة. المعاينة المحلية تتوقف بإطفاء الجهاز.

لا توجد ميزات مطلوبة أخرى مؤجلة للجزء الثالث غير تهيئة الاتصال الحقيقي والتحقق منه. تحسينات مستقبلية منفصلة عن النسخة: تخزين كائنات خاص، تنسيق حدود عدة نسخ، تشغيل نشر ونسخ احتياطي مراقبين، أو خدمة صوت بمواصفات لاحقة. لم يُضف صوت أو n8n أو حسابات طلاب أو نشر تلقائي.
