## الإعداد الفعلي

- Vercel Hobby: مجلد frontend، وإتاحة المصدر خارج المجلد لبناء backend/shared. frontend/vercel.json يثبت الاعتماديات من الجذر ويبني shared والواجهة، ثم يوجّه /api و/health إلى Render قبل مسارات React. المفاتيح لا تصل إلى React.
- Render Free في Singapore: خدمة quba-talents-api، Dockerfile في backend وسياق البناء الجذر. صورة Linux تحتوي OpenSSL وChromium والخطوط وشعار الوزارة. يبدأ الخادم بالترحيلات ثم Fastify على 0.0.0.0:10000. نشر الخادم يدوي، ونشر الواجهة تلقائي عبر GitHub بهوية صاحب الحساب المتحققة.
- Supabase Free: مشروع مستقل quba-talents داخل qdra بمعرف oxtqnopquzzllilllwml؛ PostgreSQL 17.11 وحاوية quba-private الخاصة. STORAGE_PROVIDER=supabase، فلا يعتمد نشر Render المجاني على قرص مؤقت. المحول يرفض الحاويات العامة. ملفات JPEG/PNG/WebP/PDF فقط و10 MiB، والتحقق وإعادة الترميز قبل الرفع.
- اتصال Session pooler عبر IPv4، خمس اتصالات كحد للخادم. شهادة Supabase الرسمية في backend/assets/certs/supabase-ca.crt، وNODE_EXTRA_CA_CERTS في Docker. اتصال pg يستعمل verify-full وترحيلات Prisma تستخدم sslaccept=strict وشهادة المسار المطلق؛ لم يُعطل فحص TLS.
- الترحيل الخامس يفعل RLS ويمنع anon/authenticated/PUBLIC من قراءة جداول التطبيق. الوصول إلى الطلاب والملفات من API المسؤول فقط. لا توجد حسابات للطلاب في Supabase Auth.
- إعدادات الإنتاج الخاصة في Render وفي backend/.env.cloud المحلي: DATABASE_URL وCOOKIE_SECRET وAPP_ORIGIN وSUPABASE_URL وSUPABASE_SERVICE_KEY والحاوية وإعدادات Xkiro. لا توجد أسرار متتبعة في GitHub أو صورة Docker.

اختار المستخدم قاعدة إنتاج جديدة دون نقل الحساب المحلي أو بيانات الطلاب والأعمال والمرفقات. أُنشئ حساب مسؤول إنتاج جديد، وأدخلت أسماء المشرفين التي طلبها المستخدم في إعدادات المدرسة عبر API. بيانات الدخول في backend/PRIVATE_ACCESS.md داخل الحزمة الخاصة فقط، وهو مستثنى من Git.

## التحقق وحدوده

نجح فحص الجاهزية عبر رابط Vercel والخادم، والدخول وSecure/HttpOnly وCSRF، والتسجيل والقبول المتكرر دون تكرار الطالب، والبحث والتصفية والصفحات والتعديل، ورفع صورة فعلية إلى Supabase وتنزيلها مع منع الزائر، ورفض HTML وحفظ المشرفين. نجح توليد حقيقي من Xkiro للنموذج qwen/qwen3.8-omni-flash:free ثم اعتماد السيرة وتصدير PDF فعلي على Linux (264116 بايت). البيانات التي أرسلت إلى AI في الاختبار تجريبية.

اختبار حذف طالب الإنتاج الأول لم ينفذ الحذف بسبب ترويسة JSON مع جسم DELETE فارغ في أداة الاختبار؛ واجهة التطبيق تتعامل معه بصورة صحيحة، واختبار حذف الواجهة المحلي ناجح. أداة الاختبار صُححت، لكن إعادة تنظيف طالب الاختبار المؤقت تعذرت عندما فشل نظام المراجعة التلقائية بسبب حد الاستخدام. قد يبقى الطالب «اختبار نشر تجريبي مؤقت» في الإنتاج؛ يمكن حذفه من واجهة المسؤول بعد التأكيد. لم تُنفذ إعادة التنظيف ولم يُدّع نجاحها. آخر تعديلات الوثائق والحزمة المحلية لم تُدفع إلى GitHub بعد هذا الحد؛ نسخة ZIP هي الأحدث.

## حدود الخطط والنسخ الاحتياطي

Render المجاني ينام بعد 15 دقيقة دون طلبات ويشارك 750 ساعة شهرية مع خدمات الحساب الأخرى. Supabase Free يحد القاعدة بـ500 MB وتخزين الملفات بـ1 GB، وقد يوقف المشاريع غير النشطة. الموقع يعمل عند إطفاء الجهاز ضمن حدود الخدمات، مع تأخر الاستيقاظ؛ لا يوجد ضمان تشغيل دائم في الخطط المجانية. لم تُنشأ موارد مدفوعة. حدود نموذج AI مستقلة.

نجاح سيرة قصيرة لا يثبت تحمل الدفعات الطويلة على ذاكرة 512 MB؛ التصدير محدود بعملية واحدة و20 طالبًا و60 ثانية. فحص نقل ملف كامل بحجم 10 MiB عبر وكيل الإنتاج، وحمل الدفعات، والاسترجاع من نسخة احتياطية لم تنفذ في هذه الجلسة. حدود IP خلف الوكلاء قد تتشارك بين المستخدمين؛ لا تشغّل نسخًا متعددة دون تنسيق الحدود.

هذه الحزمة الخاصة تحتوي ملفات المجلد والإعدادات والاعتماديات والبناء والمرفقات المحلية، وتستثني بطبيعتها بيانات PostgreSQL وSupabase الموجودة خارج المجلد. للنسخ الاحتياطي الفعلي صدّر القاعدة والمرفقات السحابية إلى مكان خاص واختبر الاسترجاع.
