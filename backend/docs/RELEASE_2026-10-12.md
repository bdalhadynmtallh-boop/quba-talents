# تحديث التنظيم وقاعدة البيانات — 2026-10-12

وافق صاحب المشروع على استكمال خطة قاعدة البيانات والإصلاحات الضرورية ورفع المصدر ونشره. بقيت الصفحات الحالية وخصوصية الطلاب، دون حسابات طلاب أو ميزات إضافية خارج الخطة.

## ما تغير

- فصل خدمات المجالات عن HTTP وتقسيم المخططات المشتركة؛ التفاصيل في `ARCHITECTURE.md`.
- حفظ رقم التواصل واسم مجمع ثانوية قباء مع قراءة السجلات القديمة التي لم يُستكمل رقمها.
- مفتاح UUID لإعادة إرسال التسجيل وبصمة المحتوى وقفل داخل المعاملة. يُرفض استعمال المفتاح بمحتوى مختلف. جلسة المتصفح تحفظ المفتاح والبصمة فقط، دون بيانات الطالب.
- علاقة الطلب بسنة تقديمه. لا تُملأ سنوات الطلبات القديمة بالتخمين؛ قبول سنة سابقة أو غير محددة يتطلب تأكيد الصف والسنة الحالية. التشابه في الاسم أو الجوال ينبه المسؤول ولا يحذف أو يدمج السجلات.
- تاريخ حذف الطالب في طلبه المعتمد، يسجله مشغل PostgreSQL حتى عند الحذف خارج الواجهة. سجل القبول السابق لا يعيد إنشاء طالب محذوف.
- جدول خاص `CvReview` للمراجع واسمه التاريخي والنسخة والبصمة والتاريخ وإقرار مراجعة الطالب بإشراف المدرسة. الاعتماد يتطلب النسخة الحالية ومصدرًا لم يتغير. المعتمد القديم يبقى قابلًا للقراءة مع بيان غياب سجل المراجعة.
- حقائق AI المكتسبة تطابق المدخلات الموثقة حرفيًا؛ النبذة والاقتراحات المستقبلية تخضع للمراجعة البشرية. توجد معاينة قبل الإرسال وحذف للأسماء المعروفة وأرقام التواصل والبريد والروابط من النصوص. الكشف الآلي لا يتعرف على كل معلومات شخصية؛ المعاينة البشرية ضرورية. بصمة المعاينة تمنع إرسال مصدر تغير بعد مراجعته.
- إصلاح فلاتر البحث وتحديث الموارد المتأثرة بالإعدادات وإخفاء المحتوى الخاص عند 401. تحسين أسماء عناصر الدخول للجوال وتباين الأزرار ورسائل التأكيد. حدود أجسام طلبات الطلاب تستوعب النصوص العربية المقبولة.
- اختبارات الكتابة تتطلب قاعدة `_test` صريحة. صور الاختبارات داخل النتائج المستثناة من Git ولا تعيد كتابة صور الوثائق.

## الترحيلات والنسخة الاحتياطية

الترحيلان `202610120001_school_name_phone` و`202610120002_registration_reviews` إضافيان؛ لا يعيدان بناء الجداول ولا يحذفان الطلاب أو الطلبات. الجدول الجديد يفعل RLS ويسحب المنح العامة. دالة الحذف بصلاحيات المستدعي، وليست `SECURITY DEFINER`، ولا تمنح أدوار الواجهة تنفيذها.

أُخذت نسخة خاصة لجداول التطبيق في `public` وسجل Prisma وكتالوج الأعمدة وبصمات السلامة. استُرجع 16 جدولًا و28 سجلًا في قاعدة منفصلة من الترحيلات المطابقة للإنتاج، ثم نجحت ترقيتها. لم توجد مرفقات وقت النسخ. النسخة تخص التطبيق ولا تشمل كل إعدادات منصة Supabase والأدوار. مكانها `.data/private-backup-20261012`، مستثنى من Git والنشر؛ تحفظ خارج الجهاز في مكان خاص للاحتفاظ طويل الأجل.

## الفهارس

أضيفت فهارس مراجع الطلب وسنته وحالته وتاريخه، والجوال للتشابه. لا يوجد تفرد على الاسم أو الجوال. قياس 30 ألف اسم عربي مصطنع أعطى مسحًا تسلسليًا نحو 4.3 ms مع B-tree و5.3 ms بعد GIN تجريبية. لا فائدة مثبتة، لذلك لم تُضف `pg_trgm` أو GIN إلى الإنتاج. بيئة القياس Windows/locale C وفرز ICU للعمود، بينما الإنتاج Linux/en_US.UTF-8؛ لا تعمم الأزمنة. عند نمو البيانات يعاد القياس على نسخة مطابقة. B-tree الحالي يخدم المطابقة الكاملة، ولا يفترض أنه يسرع البحث `%جزء%`.

## التحقق

نجح 58 اختبار خادم دون تخطي، وثماني رحلات متصفح على Edge تشمل انتهاء الجلسة وإخفاء المحتوى الخاص، التسجيل والاعتماد، السيرة والتحرير وPDF، إدارة السنة والكتالوج، الجوال والثيمين وRTL. نجح بناء الطرفين والحزمة المشتركة وفحص TypeScript وESLint. نجح اتصال حقيقي بمزود الصياغة بمعلومات مصطنعة دون إرسال بيانات طالب. تُستكمل نتائج النشر بعد اكتماله؛ محاكاة الجوال ليست اختبار Safari فعليًا.

حدود الخطط المجانية والحمل الكبير للملفات ودفعات PDF ومشاركة حدود IP خلف الوكيل لم تُختبر بحمل إنتاج ممثل. لم تتغير الثقة بالوكيل بالتخمين، ولم تضف ميزات سجل التحاق سنوي أو أدلة أو إدارة مقترحات المواهب.

## النشر والاسترجاع

الخادم الحالي Render Singapore، والواجهة Vercel، والمستودع الخاص نفسه. يبدأ Docker بترحيلات Prisma ثم الخادم؛ لا seed أو إعادة ضبط للقاعدة. الترحيلات إضافية، ويمكن الرجوع إلى التطبيق السابق دون حذف الأعمدة الجديدة عند الضرورة. لا تعدّل ترحيلًا منشورًا؛ الإصلاح بترحيل لاحق. استرجاع بيانات الإنتاج مؤثر في البيانات ويتطلب مراجعة السجلات المضافة منذ النسخ.
